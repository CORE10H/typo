# 演出拡張の設計メモ

2026-11-16 作成

MV・PV 向けに演出の幅を広げたときの、調査結果・設計・決めたことの記録。
もとになった資料は `mv_kinetic_typography_kit`（依頼者の手元にある設計資料一式。リポジトリには入れていない）。
依頼者から「判断は任せる。最終段階まで進めてほしい」と任されたので、資料の Stage 1〜5 を通して進めた。

## 1. 拡張前の状態と、妨げになっていた点（Stage 1：現状分析）

| 項目 | 拡張前 |
| --- | --- |
| 構成 | TypeScript + Vite。描画は Canvas 2D。動画の読み書きは WebCodecs + Mediabunny |
| 描画 | `src/engine/renderer.ts` の `Renderer` を、プレビュー（`src/app/player.ts`）と書き出し（`src/video/exporter.ts`）で共用 |
| 演出 | 行ごとに「動き」を1つ選ぶ。12種（基本型9種は `presets/basic.ts` のデータ、特殊型3種は1ファイルずつ） |
| 調整項目 | 強さ・速さの2つ |
| 自動割り当て | 歌詞の単語とテーマから動きを選ぶ（`src/core/draft.ts`） |

演出を増やすうえで妨げになっていたのは次の4点。

1. **1行に演出を1つしか持てない。** 「上昇しながら色ずれし、粒になって消える」のような組み合わせが作れなかった。
2. **登場と退場が、動きの中に固定されていた。** 退場だけを別のものに差し替えられなかった。
3. **行全体・画面全体にかかる効果が、揺れと光しかなかった。** カメラの寄り、暗転、黒帯、映像そのものの動きがなかった。
4. **文字の絵を加工する手段が、砕散の専用コードしかなかった。** 輪切り、粒、色ずれなどを足す共通の入口がなかった。

プレビューと書き出しで同じ描画関数を使う作りと、時刻から必ず同じ絵が出る作りは、そのまま活かせた。

## 2. 設計（Stage 2）

### 三層に分ける

| 層 | 中身 | 置き場所 | 数 |
| --- | --- | --- | --- |
| 動き | 文字の登場・保持・退場。1行に1つ | `src/engine/presets/` | 21 |
| 重ねる効果 | 動きの上に足す効果。1行に5個まで | `src/engine/effects/` | 27 |
| レシピ | 動き1つ＋効果いくつかを束ねた完成形。番号の参照だけを持つ | `src/engine/recipes.ts` | 15 |

資料の言う「プリセット（1つの技法）」が動きと効果、「レシピ（完成した演出意図）」がレシピにあたる。

### 効果ができること（4つの入口）

効果1つは、次の4つのうち必要なものだけを持つ（`src/engine/effects/types.ts` の `Effect`）。

| 入口 | できること | 例 |
| --- | --- | --- |
| `state` | 1文字ごとの位置・大きさ・濃さを変える | 拍で弾む、明滅、字間が開く |
| `fx` | 行全体・画面全体にかける | ゆっくり寄る、映像を暗く、黒帯、閃光、映像ごと寄る |
| `passes` | 行の写しを足して描く | 残像、色ずれ、トンネル、増殖、映り込み |
| `draw` | 文字の絵の切り方を変える | 水平ずれ、波打ち、溶け落ち、粒、破片、文字化け |

### 重ねたときの決まり

同じ項目を複数の効果が触るときの扱い。

- 位置・回転：足し合わせる
- 大きさ・透明度：掛け合わせる
- ぼかし：いちばん強いものを採る
- 文字の切り方：リストの後ろにある効果が優先。該当しない瞬間は、前の効果へ譲る
- 登場・退場を受け持つ効果：それぞれ1つまで。その間、動きの側の登場・退場は省く

### 描画方式は Canvas 2D のまま

資料は CSS・SVG・WebGL・Three.js なども候補に挙げているが、採らなかった。

- 書き出しが Xperia 5 II で合格している方式（Canvas 2D → WebCodecs）を変えると、最大の難所をやり直すことになる。
- WebGL を混ぜると、プレビューと書き出しの見た目を一致させる保証が弱くなる。
- 外部ライブラリは1つも足していない（ライセンス・保守・容量の確認が要らない）。

疑似3D（回転扉、トンネル、接近）は、大きさ・ぼかし・遠近の計算で出している。文字の厚みや本物のカメラの回り込みはできない。

### 映像そのものを動かす

「映像ごと寄る」「画面が揺れる」は、歌詞だけでなく元の映像も動かす。
`Renderer.camera(t)` が寄りと揺れの量を返し、プレビューと書き出しの両方が、映像を描く前にそれを反映する。
映像を拡大して描き、枠からはみ出た分を切り取るので、縦はめ込みの黒い帯にはみ出さない。拡大は最大 1.22 倍。

### 音楽との同期

今は BPM の目盛りだけを使う。音そのものの解析はしていない。
小節の頭をキック、2拍目・4拍目をスネアに見立てている。
実際のキックやスネアの位置を取るには音の解析が要り、スマホでの負担と精度の確認が必要なので、今回は入れていない。

## 3. データ形式

行（`LineItem`）に2項目を足した。版番号は 1 のまま（足しただけなので、古い作品はそのまま読める）。

```json
{
  "preset": "impact",
  "layers": [
    { "fx": "rgb", "amount": 0.6 },
    { "fx": "punch", "amount": 0.5 }
  ],
  "recipe": "burst"
}
```

- `layers`：重ねる効果。`fx` は効果の番号、`amount` は効かせる量（0〜1、0.5 が標準）。順番に意味がある。
- `recipe`：当てはめたレシピの番号。表示用の印。手で動きや効果を変えたら `null` に戻す。

読み込み時に検査する（`normalizeLayers`）。形のおかしいもの、同じ効果の二重がけは捨てる。
描くときも、知らない番号の効果は無視する。

## 4. 演出の提案（Stage 5）

### アプリ内の提案（`src/core/suggest.ts`）

1. 区間ごとに、曲の中での役割（イントロ・Aメロ・サビ前・サビ・間奏・アウトロ）を見立てる。区間の名前から読み、分からなければ「同じ歌詞が繰り返される区間はサビ」とみなす。
2. 行ごとに、歌詞の言葉から気分（孤独・怒り・恐怖・執着・希望・官能・混乱・秘密・高揚・静けさ）を読む。
3. カタログの全候補（レシピ15＋動き21）に点を付ける。気分・役割・派手さの合い方を足し、同じ演出の使いすぎ・続きすぎを引く。
4. 行が短すぎる、文字が多すぎる、といった制約に合わない候補は外す。
5. 選んだ理由と、別の候補2つを一緒に返す。

叩き台づくりと「おまかせで振り直す」も、この同じ仕組みを使う。
単語の一致で気分を読んでいるだけなので、文脈までは読めない。そこは次の方法で補う。

### AI に相談する（`src/core/aiexchange.ts`）

対話AI（Claude、ChatGPT など）に、歌詞の意味まで読んで選んでもらう方法。

1. アプリが依頼文（決まり、カタログ、歌詞）を作る。利用者がコピーして AI に貼る。
2. AI の返事（JSON）を貼り戻す。アプリが検査してから当てはめる。

アプリ自身は AI に接続しない。利用料も鍵も要らない。
AI に直接つなぐ方式は、利用料がかかり、鍵の扱いも要るので採らなかった。必要になったら依頼者と相談する。

## 5. 誤作動を防ぐ仕組み

- 1行に重ねられる効果は5個まで。登場・退場を受け持つ効果は各1つまで（足すと入れ替わる）。
- 効果を4個以上、または読みにくくなる効果を3個以上重ねると、注意書きを出す。
- 行の写しは10枚まで、粒子は1行110個まで、文字数の多い行では粒の升目を粗くする。
- 取っておく文字の絵は、画素数の合計で上限を設けた（約64MB ぶん）。超えたら古いものから捨てる。
- 映像の拡大は 1.22 倍まで。揺れは、映像の端が見えない範囲に収める。
- 提案と AI の案は、固定した行（🔒）を変えない。当てはめた結果は「元に戻す」で一度に戻せる。
- AI の返事は信用しないデータとして扱う。カタログに無い番号は捨てて報告する。数値は範囲内に丸める。
- レシピが存在しない動きや効果を参照していたら、そのレシピだけを無効にする（アプリは止めない）。

## 6. 足し方

| 足すもの | 手順 |
| --- | --- |
| 動き（基本型） | `presets/basic.ts` にデータを1件足し、`presets/index.ts` に1行足す |
| 動き（特殊型） | ファイルを1つ作り、`presets/index.ts` に1行足す |
| 効果 | `effects/` の該当ファイルに1つ書き、`effects/index.ts` に1行足す |
| レシピ | `recipes.ts` にデータを1件足す（プログラムは書かない） |

動きとレシピには、提案用の手がかり（`meta`：向いている気分、曲の場所、派手さ、読みやすさ、最短の秒数、最大の文字数）を必ず付ける。
描画には `Math.random` や現在時刻を使わない（`engine/util.ts` の `hash` を使う）。

## 7. 一覧

仕様書の12種：降下、滴り、鼓動、打撃、輪舞、砕散、滲み、囁き、震え、絡まり、沈降、閃光

追加の9種：疾走、上昇、接近、打鍵、弾み、圧迫、集結、回転扉、静止

### 重ねる効果（27）

| 分類 | 効果 |
| --- | --- |
| グリッチ | 色ずれ、水平ずれ、明滅、残像、文字化け |
| 歪み | 波打ち、溶け落ち |
| 奥行き | 文字のトンネル、ゆっくり寄る、傾く |
| リズム | 拍で弾む、裏拍の光、小節頭の衝撃、連打 |
| 粒子 | 粒から集まる、粒になって消える、破片になって散る、粒子を増やす |

| 画面 | 閃光カット、映像を暗く、映画の黒帯、映像ごと寄る、画面が揺れる |

### レシピ（15）

追加：蜜の滴り、壊れた信号、残像の輪舞、高鳴る鼓動、祈りの上昇

## 8. 資料の案のうち、作っていないもの

- 文字を別の語に読ませる並べ替え（「反転する意味」の後半）、文字から図形への変形
- 文字の形で映像を切り抜く場面転換（文字マスクワイプ）
- 文字の厚み、カメラの回り込みなどの本物の3D
- 音の解析によるキック・スネアの検出
- 効果ごとの細かい調整項目（今は「量」の1つだけ）、お気に入り、最近使った演出
- 1文字・1単語だけに効果をかける指定（今は行単位）
