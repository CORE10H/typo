# リリックタイポアプリ仕様書

2026-11-12 作成（2026-11-16 更新）

## 1. 概要とゴール

動画と歌詞を渡すと、歌詞演出（キネティックタイポグラフィ）の叩き台を自動で組み、スマホ上で直して書き出せるアプリを作る。

**使う人**：専門知識のない個人。まずはシーバさん本人。

**完成の定義**：3分の曲の歌詞動画を、スマホだけで30分以内に作り、文字を焼き込んだmp4として書き出せる。

**第1版で作らないもの**

- 歌声からの歌詞タイミング自動認識（精度が出にくいため。代わりにタップ同期を入れる）
- 動画のカット編集、エフェクト、BGM差し替え
- 画像へのセリフ・描き文字入れ（第2版。ただし設計は最初から見据える）
- 1文字単位の細かなキーフレーム編集

作らないものを先に決めるのは、個人開発が止まる最大の原因が「機能の膨張」だからです。迷ったらこの一覧に戻ってください。

## 2. 作り方の方針

Web技術で作り始め、最初に「実機で動画を書き出せるか」だけを検証する。だめならAndroid専用（Kotlin）に切り替える。

**Web技術で始める理由**

- 開発環境の準備がほぼ不要で、スマホのブラウザですぐ試せる
- 今のGitHub Pages運用の延長で公開できる
- 文字の描画コードを、プレビューと書き出しで共用できる
- 第2版の画像への文字入れと相性がよい

**構成（候補。確定は検証後）**

| 項目 | 候補 | 補足 |
| --- | --- | --- |
| 言語・土台 | TypeScript + Vite | 型があるとClaude Codeの修正ミスが減る |
| 文字の描画 | Canvas 2D | プレビューと書き出しで同じ関数を使う |
| 動画の読み込み・書き出し | ブラウザのWebCodecs + mp4の読み書きライブラリ | ここが最大の難所。ライブラリ選定はClaude Codeに検証させる |
| 音声 | 元動画の音声を再圧縮せずにそのまま移す | 音質劣化と音ズレを避ける |
| アプリ化 | PWA（ホーム画面に追加） | ストア公開が必要になったら後から包む |

**Android専用に切り替える条件**

次のどれかに当たったら、Web方式をやめてKotlin + Media3（Android公式の動画処理ライブラリ）に移る。

- 3分・フルHDの動画で、書き出しが最後まで完走しない
- 書き出し時間が動画の長さの3倍を超える
- 書き出した動画で音と映像がずれる

切り替えた場合、アニメーションの計算式は書き直しになる。ただし設計（データ形式、プリセットの考え方、画面の流れ）はそのまま使えるので、検証までの作業は無駄にならない。

**Web方式の制約と、アプリ版にした場合の差**

| 項目 | Web方式 | Android専用 |
| --- | --- | --- |
| 作品を開くたびに動画を選び直す | 必要 | 不要 |
| 書き出し中は画面を前面に保つ | 必要 | 作り込めば不要。ただしPowerDirectorのように、市販アプリでも前面表示を求めるものは多い |
| ストア公開 | Webアプリをアプリとして包んで公開する（段階8） | そのまま公開できる |
| 作って試す速さ | 速い。保存してスマホで開くだけ | 遅い。毎回ビルドして入れ直す |
| 開発環境 | ほぼ不要 | Android Studioの導入が必要 |

Web方式の制約は上の2つで、どちらも軽い。一方「作って試す速さ」の差は、プリセットを何十回も調整するこのアプリでは開発全体に効く。そのため、段階1の検証結果が出るまではWeb方式を維持する。検証機はXperia 5 II。

最終的なストア公開は、Web方式のままでも可能。完成したWebアプリをAndroidアプリの形に包む工程を、最後に1段階足す。

**サンプルとの違い**：先日のHTMLサンプルは、文字をページの部品（DOM）として動かしていた。この方式は動画に焼き込めない。アプリではCanvasに描く方式で作り直す。

## 3. 利用の流れ

1. **取り込む**：曲入りの動画を選び、歌詞を貼り付ける。改行で1行、空行で区間（Aメロ、サビなど）に分かれる。行の中の空白や「/」は、フレーズの区切りとして扱う。
2. **形を決める**：出力の形（横16:9のまま／縦9:16にはめ込み）とテーマを選ぶ。縦はめ込みの上下の帯は黒地。
3. **拍を決める**：BPMを入力するか、曲を流しながらTAPで取る。拍子（3/4、4/4、6/8）を選ぶ。
4. **叩き台ができる**：アプリが各行に時間とアニメーションを割り振る。時間は均等割り、アニメーションはテーマに沿って自動で選ぶ。
5. **タイミングを合わせる**：タップ同期、タイムライン、秒数入力の3通りで合わせる。
6. **直す**：気になる行だけ、アニメーションを選び直す。強さと速さを動かす。文言や区切りを直す。
7. **書き出す**：文字を焼き込んだmp4を保存する。

**タイミング合わせの3通り**

- **タップ同期**：曲を再生し、その行が歌われている間だけ画面を押さえる。歌が切れたら指を離す。押した瞬間が行の開始、離した瞬間が終了になる。指を離している間は何も表示されないので、イントロや間奏は「押さないでおく」だけで空く。1曲通せば全行の位置が決まる。
- **タイムライン**：各行が時間軸の上に帯で並ぶ。帯の端を指で動かして開始と終了を直す。帯のない部分が、歌詞を出さない時間になる。
- **秒数入力**：行ごとに「12.6秒から15.2秒」のように数字で指定する。

歌詞を出さない区間は、叩き台を作る前にも指定できる。「0秒から12秒は待機」のような**待機区間**を置くと、均等割りがその範囲を避ける。

まずタップ同期で全体を合わせ、ずれた行だけタイムラインで直す、という使い方を想定している。均等割りの叩き台は必ずずれるので、1行ずつ手で直させない作りにする。

## 4. 機能要件

第1版の柱は「取り込み、叩き台、タイミング合わせ、プリセット選択、書き出し」の5つ。そこへ縦はめ込み出力、フレーズ分割、自動配色、簡易タイムラインが加わった。縦書きは第2版に回した。

| 機能 | 第1版 | 後回し |
| --- | --- | --- |
| 取り込み | 曲入りの動画1本（mp4、480p・720p・1080p、5分まで）、歌詞の貼り付け | 音源ファイルの別取り込み、複数動画 |
| 出力の形 | 横（16:9のまま）、縦（9:16の枠に横幅いっぱいではめ込み。上下は黒地） | 正方形、上下の帯をぼかした映像や画像にする |
| 拍 | BPM手入力、TAP、拍子の選択（3/4、4/4、6/8） | BPMの自動検出、曲の途中での拍子変更 |
| 叩き台 | 時間の均等割り、テーマに沿った自動割り当て、「おまかせで振り直す」ボタン | 歌詞の意味を読んで選ぶ（AI利用） |
| タイミング | タップ同期（押している間だけ表示）、待機区間、簡易タイムライン（帯を指で動かす）、秒数入力、拍への吸着 | 歌声からの自動認識、複数段のタイムライン |
| 文字組み | 横書き、長い行のフレーズ分割（2段に並べる／順番に出す） | 縦書き、ルビ、行の中での書体の混在 |
| アニメーション | プリセット12種、強さと速さの2項目、区間への一括適用 | 1文字単位の編集 |
| 見た目 | テーマ3種、行ごとの位置（映像の上・中・下。縦はめ込みでは上の帯・下の帯も選べる）、文字サイズ、縁取りと影、映像の色に合わせた自動配色、端末内のフォントファイルの読み込み | 自由配置 |
| 素材の追加 | なし（ただしテーマと動きを、後から足せるデータ形式で作っておく） | 素材パックの読み込み |
| 保存 | 自動保存、作品一覧、元に戻す・やり直す | 作品のファイル書き出し・共有 |
| 書き出し | 元動画と同じ解像度のmp4（縦はめ込みは幅を元動画に合わせる）、進捗表示、中止 | 解像度・画質の選択、透過動画 |
| 画像への文字入れ | なし | セリフ、描き文字、吹き出し、縦書き |

**微調整を続けてもらうための決まり**

- 調整項目は「強さ」「速さ」の2つだけ。それ以上はプリセットを選び直す
- 直した行には「固定」の印を付け、「おまかせで振り直す」では上書きしない
- 区間（Aメロ、サビ）を選んで、同じプリセットやテーマをまとめて適用できる
- 2回目のサビは、1回目の設定をコピーできる

## 5. データ設計

1つの作品を1つのJSONで表す。時間は「秒」で持ち、BPMは吸着用の目盛りとしてだけ使う。

```json
{
  "version": 1,
  "title": "シロップ漬けの拷問",
  "video": { "name": "mv.mp4", "duration": 192.4, "width": 1920, "height": 1080 },
  "output": { "shape": "portrait-fit", "band": "black" },
  "beat": { "bpm": 138, "perBar": 3, "unit": 4, "offset": 0.42 },
  "writing": "horizontal",
  "theme": "dokuringo",
  "autoColor": true,
  "items": [
    { "type": "wait", "id": "w01", "start": 0, "end": 12.6, "label": "イントロ" },
    {
      "type": "line",
      "id": "l01",
      "section": "A1",
      "phrases": ["甘い夢が", "降る夜に"],
      "layout": "stack",
      "start": 12.60,
      "end": 15.21,
      "preset": "fall",
      "strength": 0.5,
      "speed": 0.5,
      "position": "middle",
      "locked": false
    }
  ]
}
```

**この形にする理由**

- 時間を拍ではなく秒で持つと、後からBPMを直しても、タップで合わせた位置が壊れない
- `version` を入れておくと、将来データ形式を変えたときに古い作品を読み込める
- `locked` は「手で直した行」の印。振り直しから守る
- `output.shape` は出力の形。`landscape`（横のまま）か `portrait-fit`（縦にはめ込み）。同じ作品から両方を書き出せる
- `beat.perBar` と `beat.unit` で拍子を表す。3と4なら3/4拍子
- `writing` は文字の向き（第1版は横書きのみ。縦書きは第2版）。`horizontal`（横書き）か `vertical`（縦書き）
- `phrases` は行をフレーズに分けたもの。`layout` が `stack` なら段に並べ、`sequence` なら順番に出す
- `position` は行の位置。`top`、`middle`、`bottom`（映像の上・中・下）、縦はめ込みでは `band-top`、`band-bottom`（上の帯・下の帯）も使える
- `type` が `wait` の項目は待機区間。叩き台の均等割りがこの範囲を避ける
- 動画ファイルそのものは保存しない。名前と長さだけ記録し、開くときに選び直してもらう

最後の点はWeb方式の制約です。ブラウザは端末内のファイルの場所を覚えておけません。作品を開くたびに動画を選び直す手間が1回入ります。

## 6. アニメーションプリセット

第1版は12種。「動き」と「見た目（テーマ）」を分けて持ち、12種 × 3テーマで36通りの印象を出す。

**動き（12種）**

| 名前 | 動き | 向く歌詞 |
| --- | --- | --- |
| 降下 | 上から1文字ずつ舞い降りる | 静かな歌い出し |
| 滴り | 文字が下へ伸びて溶ける | 蜜、液体、甘さ |
| 鼓動 | 拍に合わせて脈打つ | 感情の高まり |
| 打撃 | 奥から手前へ叩きつける | サビの頭、強い言葉 |
| 輪舞 | 文字が円を描いて回る | ワルツ、踊る |
| 砕散 | 破片になって飛び散る | 壊れる、裂く |
| 滲み | ぼけた状態から浮かび上がる | 染み込む、記憶 |
| 囁き | 小さく現れて消える | 静かな行、独白 |
| 震え | 細かく揺れて歪む | 狂気、恐怖 |
| 絡まり | 行が中心へ巻き取られる | 縛る、罠 |
| 沈降 | ゆらめきながら沈む | 溺れる、眠る |
| 閃光 | 光とともに一瞬で現れる | 刹那、転換点 |

**テーマ（3種）**

| 名前 | 配色 | 質感 |
| --- | --- | --- |
| 毒林檎 | 深紅、金、蝋燭の橙 | 金の縁取り、赤い発光、火の粉 |
| 聖堂 | 青黒、銀、月光の白 | 細い銀の縁、冷たい光、塵 |
| 蜜 | 琥珀、黒、乳白 | とろみのある輝き、滴 |

**奥行きと迫力の出し方**

前回のサンプルが平面的だった反省を踏まえ、すべてのプリセットに次の4つを標準で持たせる。

- **拡大縮小による前後の動き**：奥から来る、手前へ抜ける
- **発光と影**：文字の外側に色付きの光、下に濃い影
- **粒子**：火の粉や塵を文字の前後に散らす
- **画面の揺れ**：強い拍で文字全体をわずかに揺らす

本格的な立体表現（文字の厚み、カメラの回り込み）は第1版ではやらない。描画方式が別物になり、スマホでの書き出しも重くなるため。

**縦書きと横書き**

縦書きは第2版に回す。ただし後から足せるよう、すべてのプリセットを「行が進む向き」を基準に作る。横書きなら左から右、縦書きなら上から下。こうすると1つのプリセットが両方の向きで動く。

縦書きでは、次の文字に個別の位置調整が要る：句読点、長音記号「ー」、括弧、小さい仮名（っ、ゃ）、英数字。この位置調整と、12種すべての縦書きでの確認を第2版で行う。

**文字の位置**

位置は行ごとに選べる。横出力では映像の上・中・下。縦はめ込みでは、それに加えて上の帯と下の帯も選べる。作品全体の標準位置を決めておき、変えたい行だけ変える。

- 縦はめ込みの最下部は、ショート動画の操作ボタンで隠れるので文字を置かない
- 帯に置いた行は背景が黒一色なので、自動配色の判定を省く
- 指で好きな場所へ動かす自由配置は後回し

**自動配色**

- 行ごとに、その行が出ている間の映像を数コマ調べ、文字を置く位置の明るさと主な色を取る
- テーマが持つ配色（各4色ほど）の中から、その映像の上で最も目立つ色を選ぶ
- 映像が明るい場面ほど、縁取りと影を濃くする
- 自動で決まった色は、行ごとに手で上書きできる

動画全体で1色に決める方式は採らない。映像は場面ごとに色が変わるため、行ごとに判定する。また色を自由に作らず、テーマの配色の中から選ぶ。世界観を崩さないため。

**フレーズ分割**

- 歌詞に入っている空白と「/」を、区切りとして優先する
- 区切りのない長い行は、文節の切れ目を自動で探す（日本語の区切りを判定するライブラリを使う。候補はBudouX）
- 自動の区切りは外れることがあるので、手で直せる
- 見せ方は2通り。段に並べる（同時に表示）か、順番に出す（1フレーズずつ表示）

**素材パック（後から増やす仕組み）**

テーマと動きは後から足せる作りにする。ただし「プラグイン」のように外部のプログラムを動かす方式は採らず、設定データ（JSON）を読み込む方式にする。外部プログラムを動かす仕組みは、安全面とストア審査の両方で不利になるため。

| 素材 | 足し方 | 中身 |
| --- | --- | --- |
| テーマ | データだけで足せる | 色、書体、縁取り、発光、粒子の設定 |
| 動き（基本型） | データだけで足せる | 文字ごとの登場・保持・退場を、移動、拡大、回転、ぼかし、透明度、時間差の組み合わせで決める |
| 動き（特殊型） | アプリの更新が必要 | 砕散や絡まりのように、専用の計算が要るもの |
| 書体 | フォントファイルを読み込む | 端末内のttf、otfファイル |

第1版の12種のうち、基本型で表せるものは最初からデータで定義する。そうしておけば、新しい動きやテーマのデータをClaudeに作らせて足すこともできる。読み込み画面そのものは第1版の後（段階7）に作る。

**作りの決まり**：特殊型は1プリセット = 1ファイル。1つ足すのに他のファイルを触らなくて済む形にする。「豊富なサンプル」は、この仕組みができてから増やす。

## 7. 画面構成

画面は4つ。スマホの縦持ち、片手操作を前提にする。

| 画面 | 置くもの | 主な操作 |
| --- | --- | --- |
| 作品一覧 | 作品のカード、新規作成ボタン | 開く、複製、削除 |
| 取り込み | 動画の選択、歌詞の貼り付け欄、出力の形、BPMと拍子、テーマ選択、待機区間 | 「叩き台を作る」を押す |
| 編集 | 上：プレビュー。中：歌詞の行リストと簡易タイムライン（切り替え）。下：選んだ行の設定 | 行をタップして選ぶ、プリセットを選ぶ、タップ同期を始める |
| 書き出し | 進捗バー、残り時間の目安、中止ボタン | 保存、共有 |

**編集画面の決まり**

- プリセット一覧は名前ではなく、その行の歌詞で実際に動く小さな見本で並べる
- 行を選ぶと、プレビューがその行だけを繰り返し再生する
- タップ同期中は、次に来る行を大きく表示し、画面のどこを叩いても反応する
- ボタンは指で押せる大きさ（縦横44px以上）にする
- 横長の動画でも、プレビューは画面幅いっぱいに収める

## 8. 開発ステップ

難しいものから先に片付ける。ステップ1が通らない限り、画面やプリセットは作らない。

| 段階 | 作るもの | 合格条件 |
| --- | --- | --- |
| 0. 準備 | GitHubのリポジトリ、方針メモ（CLAUDE.md）、15秒と3分のテスト動画 | Claude Codeがリポジトリを開ける |
| 1. 書き出し検証 | 動画に固定の文字を1つ重ねてmp4で書き出すだけのページ。横のままと、縦はめ込みの2通り | Xperia 5 IIで3分・フルHDが完走。音ズレなし。所要時間が動画の3倍以内 |
| 2. 描画エンジン | 横書き、フレーズ分割、位置の選択、プリセット3種（降下、打撃、砕散）、テーマ1種 | プレビューと書き出し結果が同じ見た目。横出力と縦はめ込みの両方で、選んだ位置に文字が出る |
| 3. 取り込みと叩き台 | 取り込み画面、待機区間、均等割り、自動割り当て | 歌詞を貼って1分以内に、全行が動くプレビューが出る |
| 4. タイミング合わせ | 編集画面、タップ同期、簡易タイムライン、秒数入力、強さ・速さ、固定の印 | 3分の曲のタイミング合わせが10分以内に終わる |
| 5. プリセット拡充 | 残り9種、テーマ2種、自動配色、おまかせ振り直し | 12種すべてが実機でカクつかずに動く。明るい場面でも歌詞が読める |
| 6. 保存と仕上げ | 自動保存、作品一覧、元に戻す、ホーム画面への追加 | アプリを閉じても続きから再開できる |
| 7. 素材パック | テーマと動きのデータ、フォントファイルの読み込み | 新しいテーマを1つ、アプリを作り直さずに足せる |
| 8. ストア公開 | Webアプリをアプリの形に包む。同梱フォントの許諾確認、利用者向けの注意書き | ストアの審査に出せる状態になる |
| 9. 画像への文字入れ | 第2版として別途設計。縦書きもここで対応する | 第1版を1か月使ってから着手 |

**進め方の注意**

- 1回の依頼で1段階だけ頼む。「全部作って」は失敗しやすい
- 各段階が終わったら、必ずシーバさんのスマホで動かしてから次へ進む
- 段階ごとにコミット（記録）する。壊れたときに戻れる
- 段階1の結果は、数字（所要時間、動画の長さ、機種名）でこの文書に追記する

**段階1の結果（2026-11-16 記録）：合格**

検証機は Xperia 5 II（Android、Chrome 157）。元の動画は 1920×1080、毎秒29.96コマ、222.3秒（3分42秒）、映像 H.264、音声 AAC。

## 9. 抜けていた点と対処

最初の構想に入っていなかった13項目は、シーバさんの回答ですべて方針が決まった。新たに「素材の追加」が加わり、計14項目。

| 項目 | 決まったこと | 残る注意 |
| --- | --- | --- |
| 曲の音の場所 | 音も映像も入った動画を渡す | なし |
| 動画の向きと投稿先 | 横が基本。ショート動画は9:16の枠に横幅いっぱいではめ込む。上下の帯は黒地 | 歌詞の位置は行ごとに選べる（映像の上・中・下、上の帯、下の帯）。ただし最下部はショート動画の操作ボタンで隠れるので、文字を置かない安全域を設ける |
| 配る範囲 | まず自分用。最終的にストア公開 | ストア公開には開発者登録の費用と、公開前テストの要件がある。条件は変わるので、段階8の前に最新の内容を確認する |
| 動画の長さと解像度 | 480p・720p・1080p、5分まで | なし（1080pは段階1の実機検証で確認済み） |
| フォントの利用許諾 | フリーフォント中心、少数 | 自分の動画に使うだけなら、各フォントの「動画での利用」「商用利用」の可否を確認すれば足りる。ストア公開でアプリに同梱するのは「再配布」にあたり、フリーフォントでも禁止しているものが多い。同梱は再配布が許されたもの（SIL OFLなど）に限り、それ以外は利用者が自分でフォントファイルを読み込む方式にする |
| フォントの容量 | テーマごとに1書体 | 少数なので問題は小さい |
| 背景に負けない読みやすさ | 映像の色に合わせた自動配色を入れる | 映像は場面で色が変わるので、動画全体ではなく行ごとに判定する。色だけでは読めない場面もあるので、縁取りと影は標準で残す |
| 長い行 | フレーズに分けて、段に並べるか順番に出す | 自動の区切りは外れることがある。歌詞の空白と「/」を優先し、手で直せるようにする |
| 歌詞のない区間 | 待機区間、タップ同期（押している間だけ表示）、簡易タイムライン、秒数入力 | スマホの小さい画面でのタイムラインは、このアプリで作るのに最も手間がかかる部分。帯が1段だけの簡易版に留める |
| BPMと拍子 | 拍子は3/4、4/4、6/8から選ぶ。BPMはTAPと手入力 | 拍子の選択は当初案から入っていた（3章の手順3）。曲の途中で拍子が変わる曲は後回し |
| 書き出し中の中断 | 「画面を前面に表示したままにしてください」と表示する | PowerDirectorと同じ扱い。この制約のためだけにアプリ版へ切り替える必要はない |
| 歌詞と曲の権利 | 歌詞、曲、画像、動画はすべて自前 | 自分用の間は問題なし。ストア公開時に、利用者向けの注意書きを入れる |
| 縦書き | 第2版に回す。第1版は横書きのみ | 後から足せるよう、文字を1つずつ配置する作りと、「行が進む向き」を基準にしたプリセットは第1版から守る |
| 素材の追加 | 設定データを読み込む「素材パック」方式（6章） | データで足せるのはテーマと基本型の動きまで。専用の計算が要る特殊な動きは、アプリの更新で足す |

**率直な見立て**

- いちばん危ないのは技術ではなく、「プリセットを増やす作業が楽しくて、書き出しや保存が後回しになる」ことです。段階の順番を守ってください。
- 「豊富なサンプル」は数より質です。12種が世界観に合っていれば、50種の汎用的な動きより使われます。
- 既存の動画編集アプリ（CapCutなど）にも歌詞テロップの機能はあります。自作する価値は「自分の世界観の演出」と「拍に合った動き」にあるので、そこに時間を使うのが得策です。

## 10. Claude Codeへの最初の指示文

## 11. 決定事項のまとめ

未決事項は残っていない。

- 元動画には音も映像も入っている
- 投稿先は横長と縦長の両方。縦は横動画を9:16の枠にはめ込む。上下の帯は黒地
- 解像度は480p・720p・1080p
- まず自分用。最終的にストア公開
- 検証機はXperia 5 II
- 完成の定義は「3分の曲を30分以内」
- 歌詞の位置は行ごとに選べる。映像の上・中・下、縦はめ込みでは上の帯と下の帯も
- 縦書きは第2版。自動配色と簡易タイムラインは第1版に残す
- テーマや動きは、素材パックで後から増やせる作りにする
